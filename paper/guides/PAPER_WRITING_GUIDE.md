# 数学建模竞赛论文写作与可视化指南

> 本指南供比赛期间所有负责论文写作、润色、结构调整、图表设计、摘要撰写的 AI Agent 在**开始工作前优先阅读**。
> 指南基于 `paper/main.tex` + `paper/sections/`（第一约束，正文已按章拆分为独立文件，见第 1 章末尾对照表）、`paper/notes.md`、`paper/flowchart_samples/` 中的流程图样例，以及 `paper/samples/优秀论文合集` 中抽样精读的历届国赛优秀论文（重点权重：C题 > A题 > B题，年份越新权重越高，重点覆盖 2020–2025）整理而成。

---

## 0. 职责边界（先读这一条）

本指南的使用者是**论文编辑 / 结构设计者 / 科学写作编辑 / 数据叙事组织者 / 图表编辑**，不是建模手、算法研究员、数据分析决策者或模型优化者。

- 材料中已给出的模型、结果、参数、指标、结论 → 你的任务是把它们组织成最清晰、最有说服力、最符合竞赛规范的表达。
- 模型发生变化 → 按最新材料更新论文表达，不评价"要不要换模型"。
- **不自行发明结果、不修改建模手提供的数据、不修改变量定义、不猜测缺失数字、不自行评价模型优劣、不自行提出新模型、不把阶段性结果包装成不存在的结论。**
- 缺数据写 `[DATA_PENDING]`；缺结果写 `[RESULT_PENDING]`；图未生成写 `[FIGURE_PENDING]`。见第 10 章。

## 1. Template 解读（第一约束）

`paper/main.tex` 使用 `ctexart`（scheme=chinese）+ XeLaTeX，正文宋体、粗体强制指向黑体、行距 1.35、中文章节编号"一、二、三"。**任何结构调整必须以此为准**；样例论文若表现出更优结构，只能作为"建议修改"提出，不能擅自改变 Template。

正文不是单一文件：`main.tex` 只保留导言区宏包设置，按顺序 `\input` 各章节；每章的实际内容在 `paper/sections/` 下有独立的 `.tex` 文件，文件名前缀数字即出现顺序。**写某一章直接打开对应文件**，对照表见下：

| 正文章节 | 对应文件 |
|---|---|
| 标题+摘要+关键词 | `sections/00_abstract.tex` |
| 一、问题重述 | `sections/01_restate.tex` |
| 二、问题分析 | `sections/02_analysis.tex` |
| 三、模型假设 | `sections/03_assumptions.tex` |
| 四、符号说明 | `sections/04_notation.tex` |
| 五、数据侧写 | `sections/05_data_profile.tex` |
| 六～九、问题N的求解 | `sections/06_q1.tex` … `sections/09_q4.tex` |
| 十、模型的评价、改进与推广 | `sections/10_evaluation.tex` |
| 参考文献 | `sections/11_references.tex` |
| 附录A/B/C | `sections/12_appendix.tex` |

调整章节出现顺序只需要改 `main.tex` 里 `\input` 的排列，不需要搬动章节内容本身；编译仍是对 `main.tex` 跑 `xelatex main.tex`。

### 1.1 整体结构与每章功能

| 章节 | 功能 | 逻辑角色 |
|---|---|---|
| 标题 + 摘要+关键词 | 全文的压缩预告：问题、方法框架、逐问结果、创新点、关键词 | 独立可读，评委第一眼判断依据 |
| 一、问题重述 | 1.1 问题背景（现状→已有方案→不足→意义）；1.2 问题要求（复述题目 4 个子问题） | 证明"读懂题目"，不展开分析 |
| 二、问题分析 | 分问题逐个说明"为什么这样想、准备怎么做"；末尾放总体研究思路流程图 | 承上启下：把"要做什么"转成"怎么做"的路线图，是全文的导航 |
| 三、模型假设 | 4条左右，每条一句话假设 | 圈定问题边界，为符号说明和建模扫清障碍 |
| 四、符号说明 | 三线表：符号-说明-单位 | 建模前的词典，后文公式不再重复定义 |
| 五、数据侧写 | 全局性数据画像：来源规模/变量字典/整体数据质量/整体分布相关性概览 | 只做"对全文都成立"的处理，不为迎合某一问取舍，见第 3–4 章 |
| 六～九、问题 N 的求解 | N.1 针对本问的数据预处理 + 建立模型→求解→结果→解释 | 全文主体，一一对应"问题重述"中的四问；每问自带的数据预处理只处理本问特有的清洗/特征决策 |
| 十、模型的评价、改进与推广 | 优点/不足/改进方向/推广场景 | 全文收束，禁止在此引入新结果 |
| 参考文献 / 附录 | 文件列表、部分数据展示、代码 | 佐证与可复现性，不承担论证功能 |

### 1.2 内容归属规则（哪些内容不应该出现在某章）

- **标题+摘要+关键词**： 使用总分总结构。总：交代背景，引出本文内容。分：以‘对于问题x’开头，使用什么方法，得到什么结果，每段4~6行左右。将结果、模型、重点发现加粗体（不可泛滥）。总：“最后本文对所建立的模型进行了讨论和分析，综合评价了模型的优缺点”足矣。关键词=摘要中加粗的模型+本文主题+本文高频词（一行内）
- **问题重述**：用自己的话重述一遍问题，只复述题目要求，不出现任何本文方法/结果。禁止出现"本文采用……方法"。禁止照抄原文/
- **问题分析**：只做思路论证（为什么该用这类方法），不出现具体公式推导、不出现最终数值结果。这里的流程图是"总体思路"图，不是某一问的详细算法图。省略技术细节，给出宏观路线方案，侧重从问题到模型的过程。
- **模型假设**：只列假设 + 一句话说明依据，不展开论证；不要把数据处理的发现（如"数据中 XX 变量偏态"）当作假设写在这里，全局性发现应放入数据侧写章，只影响某一问的发现应放入该问的 N.1 数据预处理小节。
- **数据侧写**：只做"对全文都成立"的整体数据画像——来源规模、变量字典、整体数据质量（缺失/格式/明显异常的总体情况）、整体分布相关性概览，不涉及具体问题的建模方法，也不做只为某一问服务的清洗/特征决策；EDA 图表要服务于"读者对数据集形成整体印象"，不要孤立地为画图而画图。**某一问特有的缺失值/异常值处理策略、特征构造、为该问筛选的变量子集，不放在本章，放入该问求解章开头的"N.1 数据预处理"小节。**
- **问题 N 的求解**：小节 N.1 为"问题N的数据预处理"，只处理为回答本问而对数据侧写章所述数据做的针对性加工（本问特有的缺失/异常处理、变量筛选、特征构造、标准化方式等），不重复数据侧写章已交代的全局性事实；其余小节做该问的建模、求解、结果解释，不重复问题分析章已经论证过的动机（一句话带过即可），不在此处评价模型整体优劣（那是第十章的事）。标题不可超过3级。要明确给出结果。分段不能过于零散而多。
- **模型评价**：分为模型的优点，模型的不足和模型的推广三个部分。模型的优缺点侧重于优点，缺点少说，最好说一些无关痛痒的，例如复杂度过高。推广部份也用4~6行带过即可。

### 1.3 图/表/公式的位置约束

- 总体思路流程图 → 问题分析章末尾（`fig:overall-flow`）。
- 全局性数据分布/相关性图、描述性统计表 → 数据侧写章（`fig:data-eda`, `tab:desc-stat`, `tab:var-dict`）。
- 某一问特有的数据处理图/表（如该问特有的缺失/异常处理示意、特征构造对比） → 该问求解章的"N.1 数据预处理"小节内，不要放进数据侧写章。
- 符号表 → 符号说明章，一张表覆盖全文，不要每问重复定义符号。
- 模型公式、参数结果、模型比较图/结果图 → 各"问题 N 的求解"章内部，紧跟对应文字。
- 附录：文件列表表、部分数据展示表、代码（内嵌或 `\lstinputlisting` 引用外部文件，**推荐外部引用**以避免正文与代码不同步）。

### 1.4 叙事链

```
题目要求 → 问题重述（复述） → 问题分析（论证思路，出总体流程图）
   → 模型假设（圈定边界） → 符号说明（统一记号）
   → 数据侧写（全局画像：来源规模+变量字典+整体质量+整体EDA）
   → 问题1~4的求解（逐问：N.1 本问数据预处理 → 建模→求解→结果→解释，回答问题）
   → 模型评价（全局优缺点、改进、推广）
```

**Template 观察到的可选调整建议（非强制，仅供参考，需显式声明"这是建议修改"）：**
- 多份优秀样例（如 2024_C234《基于遗传算法的最优种植策略》、2025 NIPT 系列论文）在"模型评价"上采用**分问题小节**（"问题一模型评价""问题二模型评价"……)而非 Template 现在的单一大章。若某题的四问模型差异很大（例如既有假设检验又有动态规划），可建议在第十章内部按问题分小节，但仍保留统一的"十、模型的评价、改进与推广"大标题，不要拆成独立顶级章节。
- 2025 年起部分论文出现"AI 使用记录"独立章节（说明是否使用/如何使用 AI 工具），如组委会要求需要此声明，建议在参考文献之后、附录之前新增 `\section*{AI使用声明}`，仅在确认赛区要求后才加入，不擅自添加。

## 2. 论文叙事原则（可执行）

优秀论文和平庸论文的结构大纲往往相似，差异在于**信息出现的顺序和因果关系是否清晰**。核心原则：

> **读者在任意一段话，都应该知道"现在为什么要做这一步"。**

### 2.1 信息出现顺序的硬规则

1. **背景/现象先于方法**：先说"数据/现象显示了什么"，再说"因此我们选用什么方法"。禁止倒序（先甩出模型名称，再补背景）。
2. **动机先于公式**：引入任何模型前先用 1-2 句话交代"为什么不用更简单的方法/为什么这个问题需要这个方法"。参考 optout1.pdf 问题三的写法："问题二使用的……方法对应的决策方案数量过多，且无法推广至 m 道工序、n 个零配件的生产情况，故考虑将该问题转化为一个多阶段决策问题"——先指出前一方法的局限，再引出新方法，形成递进逻辑而非并列罗列。
3. **公式先于解释，解释先于结果，结果先于意义**：`定义变量 → 给出模型/公式 → 解释公式在说什么 → 代入求解得到结果 → 解释结果对问题的意义`。不允许公式后直接跳到下一个公式，必须有文字过渡。
4. **问题分析中只承诺方法，不提前剧透结果**：问题分析说"本文将建立混合效应模型研究 FF 与 GA/BMI 的关系"，不说"结果显示 BMI 与 FF 呈倒 U 型"（那是求解章的内容）。摘要例外——摘要必须提前剧透结果。

### 2.2 避免重复的规则

- 问题重述与问题分析不要重复题目原文的大段文字；问题分析应转述+加入本文视角（"这类问题相当于统计学中的假设检验问题"），不是抄题。
- 摘要中"针对问题N"段落与正文对应求解章的开篇段落，可以用近似措辞概括方法，但正文必须展开摘要中一笔带过的推导细节；摘要绝不能是正文段落的粘贴。
- 模型评价章的"缺点"部分不要重新罗列已经在求解章讲过的公式细节，只做一句话归纳性评价（如"如果将此方法迁移到较为复杂的加工流程，则精准计算的难度增加较大"）。

### 2.3 段落结构

每个论证段落遵循：**主题句（做什么/为什么）→ 证据或方法（怎么做）→ 结果（数值/公式结论）→ 解释（这说明了什么，指向下一步）**。

反例（禁止）："我们使用了 XGBoost 模型。图5是特征重要性图。表3是评估指标。"——这是实验日志式罗列，每句话之间没有因果连接词，读者不知道为什么先讲 XGBoost 又讲特征重要性。

正例：句子之间应有显式因果/递进连接："由于……，因此……""为衡量……，下面计算……""可见，……是……与……之间的权衡""综合上文，不难看出……"（这些均为精读样例中原文实际使用的过渡句式，可作为句式库参考）。

## 3. 数据处理部分怎么写（C 题重点）

> Template 把数据处理拆成两层：**五、数据侧写**（全局、一次性）+ **每问求解章的 N.1 数据预处理**（局部、按需）。写作前先判断"这个处理决策对所有问题都成立"还是"只为回答这一问才做"，据此决定放在哪一层，不要两边都写或都不写。

### 3.0 数据侧写 与 N.1 数据预处理 怎么分工

| 判断问题 | 若答案是"是" | 放在哪 |
|---|---|---|
| 换一道问题、换一种建模思路，这个结论/处理还成立吗？ | 是 | 数据侧写章 |
| 这个变量筛选/清洗策略是专门为了满足某一问的模型输入要求吗？ | 是 | 该问 N.1 数据预处理 |
| 这是描述数据集本身"长什么样"（来源、规模、字典、整体缺失/异常概况、整体分布相关性）吗？ | 是 | 数据侧写章 |
| 这是为了让某个具体模型能跑起来而做的加工（特征构造、离散化、专门的标准化、专门排除某些样本）吗？ | 是 | 该问 N.1 数据预处理 |

常见误判：把"某问建模时才发现的异常值"写进数据侧写章——若这个异常值只影响该问用到的变量/建模逻辑，应写在该问的 N.1；若该异常值是全局性问题（如某传感器在某时段整体故障，影响所有后续问题），才写入数据侧写章并在该问 N.1 中一句话引用而不重复处理过程。

### 3.1 数据概况：文字 / 表格 / 图，怎么选

| 信息类型 | 推荐载体 | 理由 |
|---|---|---|
| 数据来源（谁提供、哪个数据集） | 文字，1 句话 | 一次性信息，无需可视化 |
| 数据规模（样本数、变量数） | 文字内嵌数字，**加粗关键数字** | 如"共 147 个样本""21个变量、5460条观测"应直接写入正文句子中，不必单独成表，除非要与清洗前后对比 |
| 时间范围/采样频率 | 文字，除非需要展示"采样不均匀"这类问题本身，此时才用时间轴图或计数直方图 | 单纯报时间跨度不值得画图；若采样频率不均匀是需要论证的"数据问题"，才值得可视化 |
| 变量清单及含义 | **表格（数据字典 / 变量说明表）**，符号说明表可与之合并或紧邻 | 变量多于 5 个时必须用表，分类展示（如"孕妇基本信息类""检测指标类""胎儿信息类"），不要用大段文字逐个解释变量 |
| 变量分布/相关性/缺失/异常 | 图（见 3.2、第 4 章） | 需要视觉直觉的地方才画图 |

**原则**：数据规模等"一次性事实"用文字；变量定义等"需要反复查阅的对照关系"用表；分布、相关、缺失、异常等"需要形状/模式直觉"的内容用图。三者不要互相替代——不要把变量字典做成图，也不要把分布规律硬塞进表格数字。

### 3.2 数据侧写章的写作顺序

```
5.1 数据来源与规模：来源+样本数+变量数+时间范围，一次性事实，文字表达
5.2 变量说明：数据字典表，变量多时分类展示
5.3 数据质量概览：全局性缺失/格式/明显异常的总体情况 → 全局适用的清洗规则 → 依据
5.4 整体分布与相关性概览：描述性统计表 → 分布/相关性可视化，让读者对数据集形成整体印象
```

每个小节都要以"为什么需要交代这一层信息"开篇，以"读者由此对数据集形成了什么整体印象"收尾——本章不对任何具体问题的建模负责，避免写成某一问的预处理提前泄露。

### 3.3 每问 N.1 数据预处理小节的写作顺序

```
N.1 问题N的数据预处理：
  本问需要哪些变量/子样本（引用数据侧写章的变量字典，不重复定义） →
  本问特有的缺失值/异常值处理策略及依据（若沿用数据侧写章的全局策略，一句话引用即可，不重复过程）→
  本问特有的特征构造/离散化/标准化方式及原因 →
  处理后数据具备了什么性质，可以支撑本问接下来的建模
```

这一小节要写得简短（通常几句话到半页），只交代"和数据侧写章不一样的地方"；如果某问不需要任何针对性处理，直接用一句话说明"沿用数据侧写章处理后的数据，不做额外处理"，不必强行扩写。

## 4. 数据处理可视化指南（Data Processing Visualization Guide）

**总则：每张图必须回答一个问题（见第 6 章 Figure Purpose）。以下按数据处理步骤给出具体推荐；出现在数据侧写章还是某问 N.1 小节，按 3.0 节的判断表决定，本章图型选择本身不因位置而变。**

### 4.1 缺失值

| 场景 | 推荐图 | 说明 |
|---|---|---|
| 变量较多（>10），需要一眼看出哪些变量/哪些样本缺失严重 | **Missingness heatmap**（`seaborn.heatmap` 布尔矩阵，或 `missingno.matrix`） | 横轴变量、纵轴样本（或反过来），空白/深色块=缺失 |
| 变量不多（<10），需要精确缺失比例数字 | **Missing-value bar chart**（`barplot`，横轴变量，纵轴缺失比例%） | 比 heatmap 更适合读数值 |
| 缺失是否与时间相关（如某段时期数据系统性缺失） | **Missingness over time**（按时间分箱的缺失率折线/柱状） | 只有当"缺失是否随时间变化"是需要论证的点时才画，否则用一句话说明即可 |
| 缺失比例很低（<2%，个别值） | 不画图，一句话文字说明 + 处理策略 | 画图反而分散注意力 |

### 4.2 异常值

| 场景 | 推荐图 | 说明 |
|---|---|---|
| 单变量整体离群检测，无时间维度 | **Boxplot**（可加 `stripplot`/`swarmplot` 叠加原始点） | 快速看出上下须外的点 |
| 需要看分布形状而非只是离群点 | **Violin plot** | 揭示多峰/偏态，boxplot 掩盖形状信息时使用 |
| 异常值具有时间意义（如传感器故障期、某天数据陡变） | **Time-series plot**，标出异常点/异常区间 | **优先于 boxplot**：boxplot 把时间信息压缩掉了，如果异常点集中在某个时间段，只有时序图能揭示"这是系统性异常还是随机噪声"，直接影响是删除还是保留的决策 |
| 两变量联合异常（如 X 正常但 X-Y 组合异常） | **Scatter plot**，标出异常点 | 单变量方法查不出的联合异常，只有散点图能看出 |

### 4.3 数据分布

- **单变量分布**：Histogram（看频数/偏态直观）或 KDE（看平滑形状、多峰）；样本量小（<50）时慎用 KDE（易过度平滑）。需要同时看形状与离群点时用 Boxplot。
- **多变量分布如何避免"几十张小图"**：
  - 优先用 `subplots` 组合成一张网格图（如 3×3 grid），而不是每个变量单独占一页；
  - 只挑选与研究问题直接相关的核心变量（通常 4-8 个）展示，其余变量的分布可在附录或一句话带过（"其余变量分布均近似正态，不再逐一展示"）；
  - 若变量天然分组（如"检测类指标" vs "孕妇基本信息类"），按组分别做一张多子图网格，并列展示同组内变量。
- **log scale 使用时机**：变量存在数量级跨度（如金额、人口、面积）或右偏严重导致小值区间被压缩看不清时使用；比例/百分比/已标准化变量不要用 log scale。
- **量纲差异处理**：多变量画在同一坐标系比较分布形状前，先标准化（z-score）或使用 boxplot/violin 的分面（facet）形式而非把原始量纲叠在同一张折线图上。

### 4.4 时间变化

| 目的 | 推荐图 |
|---|---|
| 趋势 | Line plot，可叠加 rolling mean 平滑线区分趋势与噪声 |
| 波动性变化 | Rolling std / 置信带（阴影区间） |
| 周期性/季节性 | Seasonal plot（按周期分面折线）或热力图（行=周期内位置，列=周期序号） |
| 突变/结构性断点 | 在 line plot 上用竖线/阴影标出断点位置，并在图注中说明检测方法 |
| 滞后关系 | 互相关图（cross-correlation）或将滞后后的序列并列作图 |

不要用一张图同时塞入趋势+周期+突变三种信息——每张图聚焦一个时间特征，多个特征用多张子图或分步呈现。

## 5. 相关性可视化规范

### 5.1 Correlation Heatmap（`seaborn.heatmap`）

- **适用时机**：变量数 ≥ 5 且需要整体把握两两关系时；变量数 < 5 时直接用文字或散点图矩阵即可，heatmap 反而小题大做。
- **Pearson vs Spearman**：默认 Pearson（线性关系）；若变量明显非线性/存在离群点/为有序分类变量，应改用或**额外补充** Spearman，并在图注中注明用的是哪种相关系数——不要混用而不说明。二者结论不一致时（如 Pearson 弱而 Spearman 强，提示非线性单调关系）值得在正文指出，这本身是一个发现。
- **是否 mask 上三角**：矩阵对称，**建议 mask 上三角**（`np.triu`）减少视觉冗余，尤其变量数 > 8 时；变量数很少（≤5）时可不 mask，保留完整对称矩阵更直观。
- **是否标注数值**：变量数 ≤ 12 时标注具体系数值（`annot=True`）；变量数更多时数值会拥挤不可读，改为仅用颜色深浅表达，在图注中说明"颜色越深表示相关性越强"，或只标注绝对值超过阈值（如 |r|>0.5）的格子。
- **变量排序**：不要用原始录入顺序，应按聚类相似度排序（层次聚类 `clustermap`）或按变量类别分组排序，让强相关变量在矩阵中聚簇呈现，可读性远高于随机顺序。
- **变量太多时的处理**：先筛选与目标变量相关性较强或业务上关键的一个子集（如 15-20 个）画 heatmap，全量变量的相关性矩阵放入附录或不展示。

### 5.2 Scatter Plot（`seaborn.scatterplot` / `regplot`）

- 适合：两变量关系、直观判断相关性强弱、发现非线性关系、发现异常点。
- **何时加回归线**（`regplot`）：确认两变量存在需要量化的线性/单调关系，且散点图本身趋势不够直观时；回归线用于辅助读者理解趋势，不用于替代正式的回归建模章节。
- **何时用 hue 分类别**：存在明显分组因素（如男胎/女胎、不同 BMI 分段）且分组对关系形态有影响时，用不同颜色区分，同时在图注说明分组含义。
- **何时不该加回归线**：数据呈现明显非线性/非单调关系时，强行加线性回归线会误导读者；此时应保留纯散点图，或改用 LOWESS/分段拟合。

### 5.3 Pairplot（`seaborn.pairplot`）

> Pairplot 很容易变成"图很多但信息很少"——n 个变量产生 n² 个子图，超过 5-6 个变量后每个子图都太小，读者无法从中获得有效信息。

- **值得使用的情况**：核心变量数量 ≤ 5-6 个，且这些变量正是后续建模的主要自变量/因变量，需要一次性直观呈现两两关系全貌（比如问题分析阶段快速筛选自变量）。
- **变量较多时的处理**：先用相关性/业务重要性筛选出 4-6 个关键变量再做 pairplot；不要对全部原始变量不加筛选地跑 pairplot 后直接贴图。
- 若确实需要展示多变量的整体关系但变量数偏多，优先考虑 correlation heatmap + 若干张针对性 scatter/boxplot，而非硬塞一张信息过载的 pairplot。

## 6. "每张图为什么存在"原则（强制自检）

> **不要为了让论文漂亮而画图。每张图必须回答一个问题。**

**任何 Agent 在提出或制作图表前，必须先在内部（写入设计说明或工作记录，不一定进入正文）回答以下问题：**

- 这张图想证明什么？
- 它服务于哪个论点/哪一句正文陈述？
- 如果删除这张图，正文是否会失去重要信息？
- 为什么选择这种图，而不是另一种图？

**如果四个问题中任意一个答不出来（尤其第 3 条"删除后不影响正文理解"），则不应该画这张图。**

### 6.1 图表 Agent 设计协议（Figure Design）

负责提出或制作图表的 Agent，在生成图片前应先产出如下设计信息（内部记录，供论文 Agent 核对，不必逐字进入正文）：

```text
Figure ID: <编号，如 fig-eda-corr>
Purpose: <这张图想证明什么>
Related section: <对应 Template 中的哪一章/哪一问>
Main message: <一句话，读者看完这张图应该得出的结论>
Data source: <数据文件/来源，需与建模手提供的一致，不得虚构>
Chart type: <具体图类型，如 seaborn.heatmap>
X-axis: <含义及单位>
Y-axis: <含义及单位>
Grouping / hue: <是否分组，分组含义>
Annotation: <标注内容，如相关系数、样本量、显著性星号>
Expected interpretation: <预期读者解读，用于事后核对图是否达到目的>
```

示例（与最终指南文档中的风格保持一致）：

```text
Figure: Correlation Heatmap
Purpose: 展示主要水质变量间的两两相关关系
Section: 数据侧写 / 整体分布与相关性概览

Data source: cleaned_dataset.csv
Chart type: seaborn.heatmap
X-axis: 变量
Y-axis: 变量
Annotation: 相关系数数值
Expected interpretation: 深色格子对应的变量对在建模时应考虑合并/降维
```

## 7. 图表位置规范

### 7.1 基本原则

> **图应该紧跟在它第一次被解释的文字之后。** 禁止"先放图，后面两页才解释"，也禁止图注是唯一说明文字（正文必须至少用一句话点出图的核心结论，不能让读者自己从图上找结论）。

### 7.2 分类位置建议

| 图类型 | 应靠近 |
|---|---|
| 全局性数据分布/缺失/异常/相关性图 | 数据侧写章，紧跟对应文字段落 |
| 某一问特有的数据处理图（该问特有的异常处理/特征构造示意） | 该问求解章的"N.1 数据预处理"小节内 |
| 总体研究思路流程图 | 问题分析章末尾（Template 中 `fig:overall-flow` 位置） |
| 具体问题的建模流程图/框架图 | 该问题求解章的建模小节开头（先给图建立直觉，再展开公式） |
| 结果图（预测值/实际值对比、模型比较、误差分析、敏感性分析） | 紧跟"问题N的求解"章中对应的结果小节，公式求解完毕、给出数值结果之后立即呈现 |

### 7.3 图表数量控制

- **信息密度 > 图的数量**：不要让论文变成 notebook 截图集合。精读样例中信息密度高的论文（如 NIPT 2025 优秀卷）平均每 2-3 页出现一张图/表，且每张都直接服务于紧邻文字的论点。
- 一页正文中出现超过 1 张图时，优先考虑是否可以用 `subplots` 合并为一张多子图，而非并排堆砌多张独立图。
- 相关但维度不同的图（如同一变量的缺失+分布+异常）若能在一张多面板图中呈现，应合并；若信息量差异大、各自需要独立详细讨论，则拆分为独立图分别配文字论证。
- 事后自检：删除某张图后重读上下文，若论证链条仍然完整、没有断裂，说明这张图是冗余的，应当删除。

## 8. 图表类型选择表

| 论文目的 | 推荐图 | 实现（首选 Seaborn，必要时用 Matplotlib） | 最适合展示什么 |
|---|---|---|---|
| 单变量分布 | Histogram / KDE | `histplot`, `kdeplot` | 分布形状、偏态、多峰 |
| 分布比较（多组/多变量） | Boxplot | `boxplot` | 中位数、四分位、离群值 |
| 分布形态比较 | Violin | `violinplot` | 分布形状细节（多峰、偏态） |
| 两变量关系 | Scatter（+ regplot） | `scatterplot`, `regplot` | 相关性、非线性关系、离群点 |
| 时间趋势 | Line | `lineplot`（Matplotlib 更适合叠加多种统计带/断点标注） | 时间变化、趋势、周期 |
| 多变量相关矩阵 | Heatmap | `heatmap`（配 `clustermap` 做聚类排序） | 多变量两两相关性 |
| 少量核心变量的整体关系 | Pairplot | `pairplot`（≤6 变量） | 变量两两关系全貌 |
| 类别比较 | Bar | `barplot` | 类别间数值差异 |
| 分类计数 | Count plot | `countplot` | 各类别样本量 |
| 模型指标比较 | Grouped Bar / Dot plot | `barplot`（分组）或 Matplotlib 自定义 dot plot | 不同模型/方案的 MAE/RMSE/R²/Accuracy 对比 |
| 预测值 vs 实际值 | Scatter + 对角线（identity line） | Matplotlib（`plt.plot([min,max],[min,max])`叠加散点） | 拟合优度、系统性偏差 |
| 残差分析 | Scatter（残差 vs 预测值/时间） | `scatterplot` | 残差结构、异方差性 |
| 特征重要性 | 水平条形图 | Matplotlib `barh`，或 SHAP summary/beeswarm | 变量对模型的贡献排序 |
| 敏感性分析 | Line / Heatmap / Bar | 依参数维度而定：单参数用折线，双参数用热力图，离散方案比较用柱状图 | 参数变动对结果的影响程度 |
| 分组分布比较 | Boxplot + hue | `boxplot`（`hue=`分组变量） | 不同组别间的分布差异 |
| 流程/框架/逻辑关系 | 流程图 / 框图 | TikZ（LaTeX 原生，最终排版首选）或设计工具后转图片 | 问题分解、数据处理流程、建模框架、多问题递进关系（非统计图，见第 9 章） |

**不要机械限制在 Seaborn**：时间序列叠加多种统计带（原始值+滚动均值+置信区间+断点标注）、自定义对角线的预测-实际对比图、复杂多面板拼图，用 Matplotlib 直接控制更灵活；Seaborn 更适合标准统计图的快速、美观默认样式。

## 9. 流程图 / 思维导图的使用

论文视觉元素不应全是统计图。以下场景适合流程图/框图：

### 9.1 问题分析：总体思路流程图（Template 强制要求，`fig:overall-flow`）

放在问题分析章末尾，呈现"题目 → 子问题 → 方法 → 结果"的整体路线图。参考 `flowchart_samples/` 中的两张样例：

- **样例一**（4 个问题横向并列的模块化流程图）：每个问题一个色块，块内用小图标+关键词表示该问题的"数据处理→建立模型→关键产出"，块间用箭头/相邻关系表示问题间的递进依赖（如问题一的 BMI 建模结果是问题二分组优化的输入）。适用于**四问之间有明确递进/依赖关系**的题目。
- **样例二**（单一流程横向 4 阶段：数据准备→模型建立→模型求解→结果分析）：适用于**单个模型/单个问题**内部的方法论流程展示，強调"这一个模型是怎么从数据走到结论的"。

选择依据：若四问方法各异但有链式依赖 → 用样例一的"多模块并列+箭头衔接"；若重点讲清单个核心方法的内部步骤 → 用样例二的"单链条阶段图"。**不要机械套用**，需根据实际题目的问题间关系决定用哪种。

### 9.2 数据处理流程图

适合放在数据侧写章开头，一句话说明整体处理流程后配图：

```
原始数据 → 数据清洗（缺失值/格式） → 异常值处理 → 全局标准化 → 侧写完成的通用数据集 → 各问按需做 N.1 针对性处理
```

仅当处理步骤较多（≥4 步）且步骤间有分支/依赖关系需要可视化时才画；步骤简单（2-3 步、线性无分支）时一句话文字描述即可，不必画图（图表数量控制原则）。某一问 N.1 小节内部的针对性处理步骤通常只有 1-2 步，一般不需要单独配流程图。

### 9.3 全文建模框架图

若四问间存在强递进关系，可在问题分析末尾用一张总览图替代/补充分问题流程图；若四问相对独立（共享同一批数据但方法不同），可用"数据居中，四问分支向外"的辐射状结构。**必须基于实际题目结构判断，不得套用固定模板。**

### 9.4 制作建议

- 最终排版建议使用 TikZ（`main.tex` 已引入 `tikz` 包，且已提供 `\FigPlaceholder` 占位命令），保证与正文字体、配色统一，避免外部截图分辨率/字体不一致问题。
- 撰写阶段可先用占位框（`\FigPlaceholder{宽}{高}{说明文字}`）打草稿，最终提交前替换为正式绘制的流程图。

## 10. 图中应包含 / 应避免的信息

### 必须考虑
- Title（简洁陈述图在说明什么，非"图1"这种空洞占位）
- X 轴、Y 轴标签及单位
- Legend（仅在有分组/多序列时出现）
- 必要时：样本量（n=…）、数据来源、统计显著性标注（如 * / p 值 / 置信区间）

### 尽量避免
- 无信息量的大标题（如直接写"数据分析图"而不说明具体内容）
- 过多颜色（非必要不超过 5-6 种类别色）
- 过多图例项（超过 6-8 项时考虑合并类别或改用分面）
- 过小字体（导出后印刷/PDF 查看仍须清晰可读）
- 3D 图（除非确有三维空间数据不可用二维充分表达，绝大多数场景应避免，3D 图会引入视觉误读）
- 纯装饰性元素（渐变背景、无意义图标、水印类元素）
- 与正文重复的信息（图中已经清楚呈现的数字不必在正文逐字复述，正文只需指出图揭示的结论）

## 11. 模型结果怎么画（不评价模型好坏，只研究呈现方式）

### 11.1 模型比较
- 多模型/多方案指标比较：**Grouped barplot** 或 **dot plot**，每个模型一组柱/一个点。
- **不要把不同量纲的指标画在同一坐标轴**（如 MAE 和 R² 数值范围/含义完全不同），除非做了归一化并在图注明确说明；否则应拆成并排的多个子图（每个指标一个子图，横轴统一为"模型/方案"）。

### 11.2 Prediction vs Actual
- 散点图 + 对角线（identity line, y=x），点越贴近对角线说明拟合越好。
- 若为时间序列预测，额外提供实际值与预测值的**时序对比折线图**（更直观展现预测在时间维度上的偏差模式）。

### 11.3 残差分析
- Residual histogram / KDE：检查残差是否近似正态。
- Residual vs 预测值：检查是否存在异方差性（残差随预测值增大而发散）。
- Residual vs 时间：检查是否存在残差的时间自相关/系统性漂移。

### 11.4 Feature Importance
- 水平条形图（横向排列，按重要性降序），比竖直条形图更易读长变量名。
- 若建模手提供了 SHAP 结果，用 SHAP summary/beeswarm plot 呈现方向性影响（而不只是重要性大小）。

### 11.5 敏感性分析
- 单参数敏感性：折线图（横轴=参数取值，纵轴=目标/结果指标），参考 optout1.pdf 图2/图3 的 α、β 超参数敏感性折线图画法。
- 双参数敏感性：热力图（两轴为两个参数，颜色为结果指标）。
- 离散方案敏感性（如"情况1 vs 情况2"）：柱状图对比。

## 12. 文风规范

### 12.1 句子层面
- 简洁、信息密度高；避免"首先……其次……最后……"这类空泛连接词的滥用，优先使用体现因果/递进的具体连接词（"由于……因此""可见……""综合上文……"）。
- 避免口语化表达和 AI 式套话（如"值得注意的是""不难发现""众所周知"这类无信息量的套语要克制使用，仅在确实引出重要转折时使用一次，不可通篇重复）。
- 避免同一表达反复出现（如通篇都用"我们建立了……模型"，应根据语境变化措辞：建立/构建/引入/采用/提出）。

### 12.2 段落层面（同第 2.3 节）
主题句 → 证据/方法 → 结果 → 解释，四要素尽量在每个论证段落中都出现。

### 12.3 数学表达
不要只堆公式。规范流程：**文字定义变量的含义（若符号说明表已定义可省略重复定义，直接引用）→ 给出模型/公式 → 用一句话解释公式在表达什么关系 → 代入具体数值/求解方法 → 给出参数或结果 → 解释结果对问题的意义**。

反例（禁止）：连续三个公式没有中间文字过渡，直接罗列。
正例（参考 optout1.pdf 5.1-5.3 节写法）：每个公式前有"由于……"“为衡量……下面计算……"这类引导句，公式后紧跟"其中，X 表示……"的符号复述，再引出下一步逻辑。

### 12.4 公式与模型原理的详略规范（该不该给公式、给多详细）

> 基于对 `paper/samples/MinerU_Batch_Export_202608191437373/` 中 20 篇优秀论文（重点精读 2025_C132、2025_C023、2024_E010、2025_E030、2024_C094、2024_C038、2024_A066、2024_B196 等）的逐处核查整理。这是最容易被写成"要么全篇不给公式显得空洞、要么每个方法都完整推导显得臃肿"的地方，需要按角色分层处理，而不是全文统一详略。

**核心判断规则：先问该方法在本文中的角色，再决定给多少，而不是按"方法本身是否复杂"来决定。**

| 该方法扮演什么角色 | 详略处理 | 样例证据 |
|---|---|---|
| **论文核心/自建/改进模型**（本文主要创新点，读者必须理解其内部机制才能看懂后续论证） | 完整给出公式、逐项定义每个下标/符号（可配合符号说明表），并配套至少一项诊断/验证（假设检验、AIC/BIC模型比较、似然比检验、残差/正态性诊断、灵敏度分析等）；篇幅可占该问题小节的大半 | `2025_C132` 混合效应模型：给出基本形式公式后，专门用整节做模型比较（AIC/BIC表）、似然比检验（χ²、p值）、方差成分分析、随机效应正态性检验（Q-Q图）、同方差性检验，公式密度和篇幅远超同文中的 Spearman 相关系数部分。`2024_C094` 自建种植策略优化模型：目标函数按销售情形分类逐条给出公式，每个下标变量单独定义，约束条件逐条编号列出数学表达式 |
| **直接调用的成熟模型/算法**（ML模型、优化算法作为求解工具，非本文创新点） | 只给：①一句话点出核心思想或选用动机；②该方法唯一必要的"顶层"公式（目标函数/集成公式/状态转移方程/相关系数计算式），不推导内部数学细节（如梯度提升的二阶展开、决策树分裂准则、PSO速度更新的完整迭代式）；③立刻转向结果表/精度指标，不逗留 | `2024_E010` XGBoost：一句话说明选用动机，给目标函数 `Obj(θ)=L(θ)+Ω(θ)` 后直接报告 MSE/RMSE，不推导内部机制。`2025_A066` PSO：正文只给粒子编码方式+流程图，标准速度/位置更新公式"降级"进代码附录注释，不在正文数学化展开。`2024_C234` 动态规划：只给状态转移方程一条，无更多推导，重心放在复杂度声明 |
| **仅作为后续论证"输入依据"的检验/判断步骤**（如用正态性检验决定后续该用 Pearson 还是 Spearman、假设检验只用于二选一分支判断） | 可以完全不给统计量公式，只用一句话报告结论即可 | `2025_C132`：S-W 正态性检验只写"结果显示各变量显著性 P 值均小于 0.05……拒绝原假设"，不给 Shapiro-Wilk 统计量公式；`2024_B196` 假设检验整体只用四步流程文字描述（提出假设→选择检验统计量→设定显著性水平→计算p值），t检验/卡方检验只点名不给公式 |
| **相关系数类方法作为分析主线**（Pearson/Spearman 用于论证变量间关系，本身是被解读的结果而非中间判断步骤） | 给出计算公式（但只给最终计算式，不做数学推导），公式后紧跟结果表和文字解读，不展开证明 | `2025_C132`、`decrypted_C050`、`2025_C023` 均先给 Spearman/Pearson 计算公式，再直接上相关系数结果表 |

**例外情形（细化规则，不是推翻规则）**：即使某方法本身成熟、非本文创新点，若后续论证需要读者理解其内部机制的某个特定特征才能看懂结论，也要多给这一点信息。例如 `2025_E030` 中随机森林并非全文核心，但因为后文要论证"随机森林在小样本外推中不如线性模型稳定"，需要读者知道随机森林是"多棵树平均"而非线性组合，故仍给出了集成公式 `f̂(x)=(1/T)Σh_t(x)`——判断标准始终是"该信息是否是理解后续论证的必要前提"，而不是方法本身的复杂度或知名度。

**可执行操作流程**：动笔写某个方法前，先问自己四个问题（按顺序）：
1. 这是本文的核心/自建模型吗？是 → 完整公式+逐项定义+诊断验证。
2. 不是，但这是直接调用的成熟模型/算法吗？是 → 一句话动机 + 顶层公式 + 直接给结果，不推导内部机制。
3. 这只是为后续分支判断服务的检验步骤吗？是 → 可以不给公式，一句话报告结论即可。
4. 后续论证是否依赖读者理解该方法的某个内部特征？是 → 在第2/3档基础上，只多给这一点必要信息，不要因此升级成第1档的完整推导。

不要用"这个方法我了解得多/少"或"这个方法看起来高级/简单"来决定详略——详略只取决于该方法在本文论证链条中的角色。

## 13. 为什么优秀论文读起来像一篇完整论文（而非实验日志）

精读样例中，优秀论文与普通论文的核心区别，不在模型是否高级，而在于：

1. **Section opening**：每章/每节开篇先用 1-2 句话交代"这一节要解决什么、承接上文哪个结论"，不要直接扎入公式或图。
2. **Section closing**：每章/每节结尾用一句话总结"得到了什么，这对后续哪一步有用"，形成承上启下的链条，而不是戛然而止。
3. **Figure introduction**：图出现前，正文先用一句话说明"下面通过图X看XX关系/现象"，不要图片突然出现没有引导句。
4. **Result interpretation**：任何数值结果出现后，必须紧跟"这说明……"式的解释句，不能只报数字不解释含义（如"R²=0.8962"后面必须接一句它意味着模型拟合优度显著优于对比方法，而非停在数字）。
5. **Transitions**：段落/小节之间使用递进/因果连接，常见有效句式（源自精读样例，可作为句式库）：
   - "如果……，则……；但是……，可见，选择……实际上是……与……之间的权衡。"
   - "综合上文，不难看出……"
   - "为衡量……的好坏，下面计算……"
   - "本文以……为核心，充分考虑……，利用……对……进行……并确定……"（摘要中"针对问题N"段落的典型句式）

**避免"一段一个模型、一段一个表、一段一个图"变成实验日志的方法**：不要按"我做了什么"的时间顺序罗列步骤，而要按"问题→证据→方法→结果→解释"的论证逻辑组织，让每一步都是对前一步提出的问题的回答，而不是并列的操作清单。

统一叙事公式：**Problem → Evidence → Method → Result → Interpretation**，贯穿全文的每一个层级（全文、每章、每节、每段）。

## 14. 模型迭代期间，论文手如何工作（避免重复劳动）

### 14.1 Stable Content（应保持稳定，尽量不因模型调整而重写）
- 问题重述（题目背景、题目要求）
- 数据侧写章（来源、规模、变量字典、整体数据质量、整体EDA——除非建模手明确说明数据本身有变化；因为不涉及任何具体建模方法，是全文中最不该因某一问模型调整而重写的一章）
- 变量定义 / 符号说明表的框架
- 章节结构（严格遵循 Template）
- 基本问题分析的思路论证（"为什么这类问题适合用XX类方法"这一层级的论证通常不随具体模型选型的微调而改变）

### 14.2 Updateable Content（模型每次迭代容易变化的部分）
- 各问 N.1 数据预处理小节（若模型输入需求变化，如换了特征工程方式，只需重写对应问题的 N.1，不牵连数据侧写章和其他问题）
- 具体模型名称、具体参数取值
- 定量指标（MAE/RMSE/R²/准确率等）
- 结果图、结果表
- 模型比较结论
- 摘要中的具体数字（结果确定后最后更新）

### 14.3 协作规则
> **不要把暂时结果写成最终叙事。** 模型仍在迭代时，正文中涉及具体数值、具体图表的地方使用占位符（见第 15 章），待建模手确认最终结果后再一次性替换，避免反复重写论证性文字。

## 15. 论文 Agent 写作协议

**每次写作前必须：**
1. 阅读本指南 `paper/PAPER_WRITING_GUIDE.md`；
2. 阅读 `paper/main.tex` 及待写章节对应的 `paper/sections/*.tex`（结构约束，见第 1 章对照表）；
3. 阅读当前论文最新草稿（避免覆盖已有内容/避免与已有表述冲突）；
4. 阅读对应问题的最新建模结果材料；
5. 确认使用的是最新版本材料（若不确定，向用户/建模手确认，不臆测）。

**写作时的强制约束：**
- 不自行发明结果、不修改建模手提供的数据、不修改变量定义、不猜测缺失数字；
- 不自行评价模型优劣、不自行提出新模型；
- 不把阶段性/暂定结果包装成不存在的最终结论。

**占位符规范：**

| 情况 | 占位符 |
|---|---|
| 缺少数据 | `[DATA_PENDING]` |
| 缺少结果 | `[RESULT_PENDING]` |
| 图尚未生成 | `[FIGURE_PENDING]` |

占位符应带简短说明其等待的内容（如 `[RESULT_PENDING: 问题二模型的RMSE与R²]`），方便后续一次性替换定位。
