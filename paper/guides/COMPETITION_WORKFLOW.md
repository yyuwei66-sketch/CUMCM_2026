# 比赛期间论文手工作流程

> 本文件回答"论文手三天内按什么顺序、在什么时间点做什么"，是**执行时序表**。
> 内容标准（怎么写、章节归属、图表规范）见 [`PAPER_WRITING_GUIDE.md`](PAPER_WRITING_GUIDE.md)，两份文件配合使用，不重复其规则。
> 本文件不涉及评审/打分，与 [`judge.md`](judge.md) 无关。

---

## 0. 总体时间线速览

| 时间点触发条件 | 论文手动作 | 产出位置 |
|---|---|---|
| 题目选定（建模手/编程手定题后） | 写标题占位 + 一、问题重述 | 直接写入正文 `main.tex` |
| 数据到手、全局清洗基本完成 | 写五、**数据侧写**文字骨架（来源规模/变量字典/整体数据质量/整体EDA）+ 配图 | 正文 + 图片文件 |
| 每道题（问题一/二/……）建模**全部完成**（含结果） | 一次性写完该题的 **N.1 数据预处理**（本问特有的加工，若无则一句话说明沿用侧写数据）+ "问题分析"论证 + "问题N的求解"整章 | 正文对应章节 |
| 全程，只要产生新假设/新符号 | 追加进暂存文件，不直接写入正文 | `staging/assumptions.md`、`staging/notation.md` |
| 每题写完时 | 顺手记一句摘要草稿素材 + 该问模型的优点/不足/改进/推广要点 | `staging/status.md`、`staging/model_review.md` |
| 全部问题完成 | 整理 `model_review.md` 成模型评价 → 假设/符号说明搬入正文 → 摘要组装 → 附录/参考文献 | 正文 |

**核心原则**：只在某个阶段的材料"确定不会因为后续调整而整体重写"时才动笔写正文；不确定的全局性内容（假设、符号、模型评价）先进暂存文件，最后一次性搬运/提炼，避免正文里出现"半成品表格反复改"的情况。

## 1. 暂存目录 `paper/notes/staging/`

四个文件，职责单一：

- **`assumptions.md`**：模型假设草稿池，按产生顺序追加，不去重、不排版，最后统一整理成正文"三、模型假设"的 4 条左右精简版。
- **`notation.md`**：符号说明草稿池，每次建模手/编程手引入新符号就补一行，最后去重整理成正文"四、符号说明"的三线表。
- **`model_review.md`**：模型评价草稿池，每问求解章写完时顺手记录该问模型的优点/不足/改进/推广要点，最后统一提炼整理成正文"十、模型的评价、改进与推广"。
- **`status.md`**：总控台账，见第 5 章，写作过程中随时更新，是应对中途大改动的核心工具。

已建好四个空模板文件，直接在其中追加内容即可，不需要额外新建文件。

**为什么模型评价也要暂存，而不是收尾阶段现想**：模型评价章要求"全局性评价、不引入新结果"，写作时最怕的是收尾阶段时间紧张，凭最后印象仓促补写、遗漏中间某问已经暴露过的局限。每问写完时评价要点还新鲜，顺手记一笔成本很低；收尾阶段只需要通读草稿池、去掉重复、提炼出真正贯穿全文的评价，而不是从零回忆四问各自的优缺点。

## 2. 逐阶段详细流程

### 阶段 0：题目公布 → 选题确定

- 触发条件：建模手、编程手选好题目（如确定做 C 题）。
- 动作：
  1. 打开 `sections/00_abstract.tex`，把题号、题目名称填入标题（正式编译入口是 `main.tex`，它按顺序 `\input` 各 `sections/*.tex`，见第 7 章）。
  2. 写"一、问题重述"：1.1 问题背景（照题目材料转述现状/意义，不早于此阶段能写，题目材料本身已给出）、1.2 问题要求（逐条复述子问题）。
  3. **不要在此阶段写摘要**——此时没有任何方法/结果可写，写了也会在最后全部重写。
- 风险：极低。问题重述几乎不会因为后续建模返工——除非最后发现最初理解题目有偏差（罕见），一般不需要触碰这部分。

### 阶段 1：数据到手 → 全局数据清洗基本完成

- 触发条件：编程手/建模手交付清洗后的数据集，**全局性**缺失值处理、异常值处理、格式标准化策略已定（不含只为某一问服务的加工）。
- 动作：
  1. 按 `PAPER_WRITING_GUIDE.md` 第 3 章顺序写"五、数据侧写"：5.1 数据来源与规模 → 5.2 变量说明 → 5.3 数据质量概览 → 5.4 整体分布与相关性概览。
  2. 每小节按"为什么需要交代这一层信息 → 做了什么 → 读者由此对数据集形成了什么整体印象"的结构写，**具体数字、图表暂时可以先用占位符**（`[DATA_PENDING]` / `[FIGURE_PENDING]`），结构性论证先写定。
  3. 需要出图的地方，先按第 6.1 节 Figure Design 协议记录设计信息，再让图表 Agent 产图。
  4. **严格排除只为某一问服务的处理决策**——若某个清洗/筛选动作只是"为了满足问题 N 的模型输入要求"，不写进本章，留到阶段 2 该问的 N.1 小节；判断依据见 `PAPER_WRITING_GUIDE.md` 3.0 节判断表。
- 风险：**中**（低于旧版单一"数据预处理"章）。全局层内容本身变动概率不高；即使某问后续需要新的加工方式，因为已经隔离进各问自己的 N.1 小节，不会牵连本章已写好的内容，见第 4 章。

### 阶段 2：某道题建模全部完成（含结果）

- 触发条件：建模手/编程手对问题 N 的模型已经跑通，结果（数值/方案/图）已确定（哪怕是阶段性最终结果，非中途调参过程）。
- 动作（一次性完成，N.1 数据预处理、问题分析、求解合并写，不拆多次动笔）：
  1. 先写该问求解章开头的 **N.1 数据预处理**小节：本问用到哪些变量/子样本（引用数据侧写章的变量字典，不重复定义）→ 本问特有的缺失/异常处理或特征构造 → 依据。**若本问不需要任何针对性处理，一句话说明"沿用数据侧写章处理后的数据，不做额外处理"**，不强行扩写。
  2. 写"问题分析"中对应问题 N 的小节：为什么用这类方法（论证，不剧透结果）。
  3. 紧接着写"问题 N 的求解"其余部分：建模 → 求解 → 结果 → 解释，按 `PAPER_WRITING_GUIDE.md` 第 2、12、13 章的段落结构和过渡句式写。
  4. 结果暂未最终确认时用 `[RESULT_PENDING: 具体等待内容]` 占位，禁止把阶段性数字当最终结论写死（第 14.3 节协议）。
  5. 在 `staging/status.md` 里记录一句"本问摘要草稿句"（用"本文以……为核心，充分考虑……"句式打底），供最后组装摘要用。
  6. 在 `staging/model_review.md` 里顺手记录该问模型的优点/不足/改进方向/推广场景要点（不必成句），供最后整理模型评价章用。
  7. 更新 `staging/status.md` 中该问的状态为"已完成初稿"，并标注依赖的数据版本（见第 5 章）。
- 关于"问题分析写在什么时候"：**统一在该问建模完全做完之后，与 N.1 数据预处理、求解章一起写**，不提前、不分多次动笔——虽然问题分析理论上方法思路一定下来就能写，但实践中拆开会导致重复打开同一章节多次、上下文来回切换成本更高，合并成一次性任务更省心。

### 阶段 3：全部问题完成 → 收尾

- 触发条件：问题一到问题 N（通常 3-4 问）全部完成初稿。
- 动作顺序（有依赖，必须按此顺序）：
  1. **模型评价**：通读 `staging/model_review.md` 里各问积累的要点 + 全部问题章节，去重、提炼出真正全局性的优缺点/改进/推广，写成正文"十、模型的评价、改进与推广"，不引入新结果。草稿池里逐问记录的零散要点不能直接堆进正文——只有多问共性的、或确实值得单独一提的关键局限才保留，琐碎的、已在求解章讲过公式细节的条目做归纳性合并（呼应 `PAPER_WRITING_GUIDE.md` 2.2 节"不要重新罗列已经讲过的公式细节，只做一句话归纳性评价"）。
  2. **假设/符号说明**：整理 `staging/assumptions.md`、`staging/notation.md`，去重、精简、排版成正文表格，插入"三、模型假设""四、符号说明"对应位置。此时才整理是因为所有问题都做完后才能确认哪些假设/符号是真正贯穿全文的，避免中途整理了又要因为后面新增内容返工。
  3. **摘要**：把 `staging/status.md` 里各问的摘要草稿句取出，扩写、补最强数字（此时数字已定稿，不会再变）、加创新点，组装成完整摘要。
  4. **附录/参考文献**：整理文件列表、部分数据展示、代码引用。

## 3. 数字/占位符怎么处理（沿用现有协议，不额外加系统）

沿用 `PAPER_WRITING_GUIDE.md` 第 15 章的占位符规范（`[DATA_PENDING]` / `[RESULT_PENDING]` / `[FIGURE_PENDING]`），不引入额外的宏定义/集中数字管理系统——因为各题关注点不同，正文里重复出现的相同数字本来就不多；而且没有最终数据时你也无法审校文本是否表述准确，提前抽象成变量反而增加不必要的间接层。

**唯一要求**：占位符必须带具体说明（如 `[RESULT_PENDING: 问题二模型的RMSE与R²]`），保证最后替换时能一次定位，不需要靠记忆。

## 4. 中途大改动怎么办（核心：减小准备阶段的负担）

典型场景：问题一、二已经写完，此时数据新增了一种处理方式（如换了插补方法、新增了一类特征），导致前面的数据侧写章描述、EDA图、甚至已完成问题的结果解释都要跟着调整。

**Template 现在把数据处理拆成"五、数据侧写"（全局）+ 各问"N.1 数据预处理"（局部）两层，本身就是应对这类改动的第一道防线**：一个只影响某一问的加工方式变化（如问题三换了特征构造方式），只需重写问题三的 N.1 小节，不会牵连数据侧写章和问题一、二；只有真正全局性的变化（如原始数据缺失值处理策略整体调整）才需要碰数据侧写章，此时才可能牵连下游多问。

### 4.1 提前做的准备：给 status.md 打版本标记

在 `staging/status.md` 里，每个已完成章节旁标注它依赖的"数据版本号"（v1/v2/…，由建模手/编程手每次数据有实质性变化时递增并通知论文手）。这样发生变更时，直接筛 `status.md` 里"数据版本 < 当前版本"的行，就是需要检查的章节清单，不需要凭记忆判断影响范围。

### 4.2 变更发生时：先分类影响程度，再决定动作

| 变更类型 | 判断标准 | 需要的动作 |
|---|---|---|
| 仅参数/超参数微调，方法不变 | 模型结构、数据处理逻辑都没变，只是数值结果变了 | 只替换占位符对应数字/重新生成图，正文论证性文字不动 |
| **局部**数据处理方式变化（只影响某一问，如问题三换了特征构造方式） | 数据侧写章不用改，只是问题 N 的 N.1 小节里的加工逻辑变了 | 只重写该问的 N.1 小节；若该问下游的结论方向因此改变才连带重写该问求解章对应段落；**不影响数据侧写章和其他问题** |
| **全局**数据处理方式变化（如换了整体插补方法、原始数据整体缺失值策略调整） | 数据侧写章本身的处理逻辑变了 | 数据侧写章对应小节重写；逐个检查每问的 N.1 是否引用了被改动的全局结论，若引用了先确认"结果是否仍然成立"，方向不变只替换数字，方向变化才重写下游解释文字；摘要对应句子最后统一更新（因为摘要本来就留到最后写） |
| 建模方法整体替换（非调参，换了模型类别） | 该问从头到尾方法都不一样了 | 该问的问题分析小节 + 求解章整章重写（含 N.1）；同步修正 `staging/model_review.md` 中该问的要点（旧模型的优缺点条目作废）；不影响其他问题章节 |

判断依据用一句话概括：**改动是否改变了"为什么用这个方法"这句话本身**——没变，只动数字；变了，重写对应章节的论证文字。

### 4.3 前置优化：写作时就降低耦合

除了事后应对，写作习惯本身也能减少连锁反应：

- **能局部解决的加工不要放进数据侧写章**——这是最主要的解耦手段，按 `PAPER_WRITING_GUIDE.md` 3.0 节判断表严格执行，从源头上让大多数改动只影响一问的 N.1，而非牵连全局。
- 数据侧写章每个小节结尾明确写"这一层信息可能会被后续第几问的 N.1 引用"，让下游依赖关系在文字里是显式的，变更时能直接搜索定位受影响段落，不用通读全文找。
- 各问 N.1 小节引用数据侧写章的结论时，用"根据数据侧写阶段的分析，变量X呈现……"这类**概括性转述**而非逐字复制粘贴数字，这样数据侧写章数字变了，下游只需确认转述的定性结论是否仍成立，通常不需要改动下游文字本身。
- 摘要留到最后写（第 2 阶段已定），从根源上避免了"数据一变，摘要也要跟着改一遍"的情况。

## 5. `staging/status.md` 使用说明

这是贯穿全程的总控台账，建议结构（模板文件已包含）：

- 每问一行：状态（未开始/建模中/初稿完成/待终审）、依赖的数据版本号、摘要草稿句、待办。
- 一个"全局待办"区：记录假设/符号说明/模型评价的临时条目、跨问题的一致性问题（如两问用了不同的符号表示同一变量，需要统一）。若某问的模型评价要点因建模方法整体替换而需要作废重记，也在这里标注一笔，提醒收尾阶段整理 `model_review.md` 时跳过。
- 一个"变更记录"区：每次发生第 4.2 节所述的变更时，追加一条"什么变了 → 影响了哪些章节 → 处理状态"，避免同一变更的影响范围需要重新推导两次。

## 6. 与 `PAPER_WRITING_GUIDE.md` 的分工

- 本文件回答"**什么时候**做"；`PAPER_WRITING_GUIDE.md` 回答"**怎么**做（写成什么样）"。
- 写作前先看本文件确认当前处于哪个阶段、该做什么；动笔时按 `PAPER_WRITING_GUIDE.md` 的内容/文风/图表规范执行。
- 两份文件都在 `paper/notes/`，写作 Agent 应在每次动笔前依次阅读：本文件（确认时序）→ `PAPER_WRITING_GUIDE.md`（确认规范）→ 待写章节对应的 `paper/sections/*.tex`（确认结构，见第 7 章对照表）→ 最新草稿（避免冲突）。

## 7. 正文文件结构（`main.tex` + `sections/`）

正文不再是单一 `template.tex`，已拆成 `paper/main.tex`（编译入口，只含导言区宏包设置 + 按顺序 `\input` 各章节）+ `paper/sections/` 下每章一个独立 `.tex` 文件，方便直接定位、编辑单一章节而不用在几百行的大文件里滚动查找。**写某一章时只打开对应文件，不需要打开 `main.tex`**；改变章节顺序只需要调整 `main.tex` 里 `\input` 的排列，不需要搬动内容本身。

| 正文章节 | 对应文件 |
|---|---|
| 标题+摘要+关键词 | `sections/00_abstract.tex` |
| 一、问题重述 | `sections/01_restate.tex` |
| 二、问题分析 | `sections/02_analysis.tex` |
| 三、模型假设 | `sections/03_assumptions.tex` |
| 四、符号说明 | `sections/04_notation.tex` |
| 五、数据侧写 | `sections/05_data_profile.tex` |
| 六、问题一的求解（含 6.1 数据预处理） | `sections/06_q1.tex` |
| 七、问题二的求解（含 7.1 数据预处理） | `sections/07_q2.tex` |
| 八、问题三的求解（含 8.1 数据预处理） | `sections/08_q3.tex` |
| 九、问题四的求解（含 9.1 数据预处理） | `sections/09_q4.tex` |
| 十、模型的评价、改进与推广 | `sections/10_evaluation.tex` |
| 参考文献 | `sections/11_references.tex` |
| 附录A/B/C | `sections/12_appendix.tex` |

编译命令不变，仍是对 `main.tex` 跑 XeLaTeX（`xelatex main.tex`），产物是 `main.pdf`。
